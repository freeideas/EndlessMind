## Where things stand

- **Running:** nothing but the website. endlessmind.com serves `site/` (one home page) and `docs/` from ordinarydata; deploy steps in [deploy/README.md](deploy/README.md).

## Next: build these four together

1. **The EntryPortal:** one self-contained HTML file following "Rules for EntryPortals" in PROTOCOL.md. Setup (make a phrase and check it was written down, or accept one), non-extractable key in IndexedDB, persistent-storage request, sign in from `#url=`, sign records from `#sign=` with the public switch, keep, save and load records, burn an identity (player types the phrase again). It reads no QR codes itself; the phone's Camera app opens its link. It may import nothing at run time, so the word list and signing code are inlined (copied from `shared/`) or the file is assembled from `shared/` by a small script; decide which keeps it easiest to review.
2. **A realm library:** one small module a realm includes to get sign-in in about 30 lines: one-time join codes (two-minute expiry, single use), QR code drawing, checking sign-in notes, the claim flow (propose unsigned, realm signs after the player), serving the realm card and public list, refusing burned IDs. For QR drawing, take a well-known open-source encoder with a compatible license rather than writing one.
3. **An example realm:** a tiny, original game using the library (for example "Lantern Garden": plant glowing seeds, earn an achievement after ten). It must exercise guest play, QR sign-in, "sign in on this computer", claiming a record, and the public list.
4. **Tests:** unit tests for notes, records, join codes and expiry; a browser test (Playwright, run with `uv`) driving two browsers, one as the PC and one as the phone, through the whole loop.

Then a real-world run: EntryPortal at `endlessmind.com/EntryPortal/1/` (a fixed address per version), the example realm at an address such as `garden.endlessmind.com` (Caddy on ordinarydata), tried with a Windows PC and an iPhone. The point is to test QR sign-in and Safari's storage before designing hosting.
